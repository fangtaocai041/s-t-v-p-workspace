# parallel-farm — 并行子智能体工作流

## 背景
当一个问题可以从多个独立角度调查时，串行调查浪费时间且 context 膨胀。本 skill 将任务拆分为多个独立子问题，并行派发子 agent 调查，只取最终结论汇总。

## 使用方式
```
/run_skill name:parallel-farm arguments:"你的研究问题"
```

## 工作流程

### 1. 拆解任务（父 agent 做）
将用户的问题拆为 **2-4 个独立子问题**，每个子问题：
- 可以独立调查，不依赖其他子问题结果
- 有明确的搜证范围（文件名/目录/搜索关键词）
- 产出形式确定（一段结论 + 证据引用）

### 2. 并行派发（父 agent 调用 run_skill）
对每个子问题调用一次 `run_skill`：
```
run_skill name:explore arguments:"子问题描述 + 范围限定"
```
每个 `explore` 在隔离子 agent 中运行，互不干扰。

### 3. 汇总结论（父 agent 做）
所有子 agent 返回后，父 agent:
- 按子问题组织输出
- 合并重叠发现
- 标记矛盾点（如果有）
- 给出综合结论

## 拆解原则
| ✅ 适合并行 | ❌ 不适合并行 |
|------------|-------------|
| 不同代码模块的调查 | 需要前一步输出的多步流程 |
| 对比分析（A vs B） | 逐步调试 |
| 多维度审计（安全 + 性能 + 正确性） | 因果关系链条 |
| 不同技术方案的调研 | 单线程推理题 |

## 示例

### 题目：审查这个代码库的安全性和性能
拆解：
1. explore "扫描所有 API 路由，检查认证和鉴权是否完整 — src/api/ 目录"
2. explore "检查数据库查询是否有 SQL 注入风险 — src/db/ 目录"
3. explore "检查文件上传和处理逻辑是否有路径穿越 — src/files/ 目录"

### 题目：对比两种 OCR 方案
拆解：
1. explore "分析 baidu_ocr.js 的实现：接口调用、错误处理、返回格式"
2. explore "分析 paddle_local.js 的实现：本地运行、依赖、性能"

## 数量限制
- 同时派发不超过 4 个子 agent（工具调用并发限制）
- 如果任务需要 >4 个分支，先合并相似分支
